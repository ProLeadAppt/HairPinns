# HairPinns signed publishing and durable IndexNow design

Design only, separately reviewable from PR95. Base PR95 `85daa34fcb48d159c3ed830090d1442d2f4c7ad2`, whose parent preserves actual deployed PR94 `d44488c92ee5bbdedc0024a23d1edf0f4f4869fb`. This document changes no endpoint, configuration, credential, state store or notification behaviour. Automatic Hair setup remains excluded from PR95's proposed release.

## Existing exposure and compatibility

The existing `/api/indexnow` rewrite and underlying function accept unauthenticated JSON POSTs from any caller. Wildcard CORS permits browsers; removing CORS would not authenticate nonbrowser callers. The cap500 and canonical-host guard prevent arbitrary hosts but allow repeated submission of arbitrary paths on hairpinns.com. No request authentication, durable receipt ledger or source-event association was found. No abuse is asserted without evidence and no live POST was used to assess it.

A future implementation should stop forwarding from both `/api/indexnow` and `/.netlify/functions/indexnow`, returning410 without CORS or upstream access, and move sending into a private module used only by Netlify's event function. This intentionally changes existing operator relay behaviour and requires compatibility/release approval; neither route is changed by this document. Audit repository calls and owner-managed external scripts before deciding that migration. Keep manual operator submission separate: replace the full-sitemap operator script with a reviewed one-URL/delta local CLI that has no public relay and requires a separately approved exact batch. No browser/view/visitor-triggered submission.

## Trusted event and key reuse

Subscribe through Netlify's native deploy-succeeded event function (legacy filename is supported; choose its payload contract explicitly, or use the typed handler after validating background support). Netlify generates and verifies the JWS before invoking event functions; do not implement a public JSON endpoint that trusts payload fields or a header alone. No extra authentication secret/PAT is necessary for the platform event. Payload validation supplements platform caller authentication: exact Hair siteID from verified metadata, contextproduction, stateready, nonnullpublished timestamp, HTTPS apex hairpinns.com and40-character sourceSHA. A manually released artifact with commit_ref:null must stop until it carries an independently verified source marker; do not infer the SHA from a deploy title.

Normal build writes only `/.well-known/indexnow-release.json` with host/SHA. Wait60seconds, then require that exact live marker before and after snapshot collection. Reject old/preview/branch/failed/unpublished/wrongsite events and mixed/superseded releases. IndexNow mode defaults dry-run; INDEXNOW_ENABLED defaults absent/false. Do not add visitor-facing trigger paths or build-hook notifications.

Reuse the existing root public verification file and location legitimately discovered in PR95 source and already verified200/plain-text/exact-key match. No new key, root filename change or duplicate environment/secret field. Place the exact existing path in site-specific source configuration without logging its value. Read only that HTTPS apex path, no redirect; require200, plain-text, bounded130-byte body, UTF-8/allowed8–128 ASCII key characters, no BOM/HTML/placeholders/multiple lines. The derived key and explicit existing keyLocation are used in the POST and never treated as a Bing API credential. Recheck proof before a live batch. No wildcard host or www/apex substitution.

## Durable state on the existing platform

Use native Netlify Blobs in a proposed site-wide `indexnow-production-state` namespace. Existing package.json already includes @netlify/blobs; validate the locked SDK supports conditional writes before implementation, adding no dependency/vendor/token if it does. Native runtime binding supplies access, no copied PAT. Review current function/storage allowance before approved use; no plan upgrade or newpaidservice. Do not reuse catalogue-sync lock/state names or modify its webhook/HMAC flow.

State version1 holds host, accepted release, canonical page fingerprints, receipt ledger and optional pending intent. Strong reads plus ETag conditional writes serialize the single writer; acquire a lock with onlyIfNew/onlyIfMatch and release only with the acquired ETag. A crash leaves a blocking lock needing explicit reconciliation; no unsafe TTL steal. A persisted pending intent likewise blocks automatic retry. No exactly-once claim: a process can fail after an accepted POST but before receipt storage; pending state makes this visible and prevents automatic duplicate delivery.

An explicitly approved initial baseline observes production pages and writes fingerprints with zero submissions; missing baseline stops live mode. Recursively enumerate current page sitemaps, exclude image/LLM documents and foreign hosts, validate canonicalHTML200/no noindex and fingerprint rendered text/metadata/links/schema, ignoring build timestamps/hydration. Select added/changed pages; separately probe disappeared pages and notify only verified404/410, holding redirects and uncertain cases. Do not infer deletion from sitemap counts or full-sitemap-submit every publication.

Before each bounded500-URL POST, persist deterministic intent(host/release/URLs/content hashes); after200 or202, persist a distinct receipt and advance only those fingerprints.202 is keyvalidationpending, neither response is indexing. Error/timeout leaves pending intent and no automatic retries. Public logs contain eventSHA, counts and receipt status only, no key/body or user data. Catch background failure safely to avoid automatic Netlify retry forwarding; reconcile explicitly.

## Concrete future files and acceptance gate

Proposed code scope: event function, private sender/host config, conditional Blobs adapter, generated build marker, retirement of old relay routes, manual-operator migration and focused tests. Reuse current canonical/render/sitemap behaviour and public verification key; no blanket404 redirects, account/provider permissions, Shopify credentials or Wizard changes.

Local tests must establish disabled/preview/unpublished/wrongsite/SHA paths perform no HTTP/store writes; forged direct relay requests never forward; exact-path key reading fails closed; changed-only batches and verified removals; strong lock races/restart; persist-before-POST and pending-on-ambiguity; superseded markers stop; migrated manual CLI emits only its explicit batch. Run existing function/full regressions and quality/trust checks. Hair's existing local full build remains blocked at sitemap generation without the approved build-time Storefront binding; later stages cannot be claimed. Do not read/copy/invent a token to overcome it.

Before production security behaviour changes: review the concrete implementation and compatibility, then separately approve its exact publication with automatic notifications disabled. Verify both retired public paths cannot forward, and test that unsigned calls cannot invoke the signed event handler. Actual Netlify signature/background/event-shape enforcement must be checked on an approved hosted candidate; unit mocks cannot prove it. Then separately approve baseline state writes, a signed production event test for only https://hairpinns.com/ (temporary mode/flag and publication/reset are each explicit), and finally automatic activation after end-to-end/state recovery results. None of these approvals are implied by a design or PR95 release.
